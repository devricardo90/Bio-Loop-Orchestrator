# M10 - Estruturacao da Continuidade Estrategica Pos-M9

## Status

PLANNED

## Objetivo

Abrir a nova fase do projeto sem perder contexto, sem misturar prioridades e sem comprometer a integridade do que ja foi validado ate o fechamento limpo do pos-M9.

## Finalidade

Criar uma organizacao clara das proximas evolucoes do projeto em 3 frentes independentes:

- `BACKLOG4` - Piloto / Produto / Operacao
- `BACKLOG5` - Hardening Tecnico / Arquitetura
- `BACKLOG6` - UX / Figma / Experiencia

## Principio central

M10 nao e uma milestone de feature isolada.

M10 e uma milestone de organizacao estrategica, preservacao de contexto e definicao das proximas frentes de evolucao do projeto.

## Contexto de entrada

O projeto encerrou M9 com baseline limpa, incluindo:

- trilha principal buyer / seller / admin validada
- ingestao de dados reais validada
- piloto/profile operacional documentado
- gate consolidado de browser validado
- clean-up documental pos-M9 concluido
- ausencia de nova milestone aprovada automaticamente

## Escopo de M10

Entram em M10:

- documentacao da nova fase
- separacao formal das 3 frentes
- definicao de funcao de cada backlog
- definicao de regras de atencao por frente
- definicao de subagentes por frente
- definicao de contexto compartilhado obrigatorio
- definicao de gates de protecao entre frentes

Nao entram em M10:

- execucao de novas features
- refactor estrutural direto
- redesign direto
- abertura automatica de tasks `READY` sem decisao do gatilho

## Criticos de aceitacao

- `docs/ops/BACKLOG4.md` documentado
- `docs/ops/BACKLOG5.md` documentado
- `docs/ops/BACKLOG6.md` documentado
- funcao de cada backlog claramente separada
- regras de atencao registradas
- subagentes especializados definidos
- contexto compartilhado obrigatorio definido
- gates de protecao entre frentes documentados
- nenhuma execucao iniciada sem aprovacao do gatilho

## Direcionamento aprovado pelo gatilho

- `BACKLOG4` e a frente principal ativa
- `BACKLOG6` e a frente imediatamente seguinte
- `BACKLOG5` permanece documentado, mas nao priorizado neste momento
- hardening adicional e isolamento seller/jobs so entram por risco observado, nao por impulso arquitetural

## Regras obrigatorias

- nao misturar frentes sem decisao explicita do gatilho
- nao promover `DONE` sem gate real
- nao promover `READY` com dependencia aberta
- nao perder o contexto funcional validado ate M9
- preservar buyer, seller, admin, ingestao real, jobs e gates ja validados
- exigir que cada subagente compreenda o projeto antes de executar

## Gates de protecao entre frentes

### Produto / Piloto -> UX

So abrir execucao de UX/Figma se:

- a narrativa operacional principal estiver definida em `BACKLOG4`
- os fluxos reais a serem refinados estiverem explicitados
- nao houver mudanca estrutural em paralelo alterando os mesmos fluxos

### Produto / Piloto -> Hardening tecnico

So abrir execucao de `BACKLOG5` se:

- houver risco observado em demo/piloto ou em gates reais
- o problema estiver descrito como risco verificavel
- a task tecnica tiver escopo pequeno e impacto cruzado mapeado

### Hardening tecnico -> UX

Nao rodar redesign/ajuste de experiencia em cima de fluxo instavel ou endpoint ainda em mudanca.

### Qualquer frente -> Execucao

Nenhuma task sai do estado de proposta sem:

- objetivo claro
- dependencias fechadas
- criterios de aceitacao objetivos
- aprovacao explicita do gatilho

## Subagentes por frente

- `BACKLOG4`: Orchestrator + Product/Ops Agent + Frontend Agent + QA Agent
- `BACKLOG5`: Orchestrator + API Agent + Infra Agent + DB Agent
- `BACKLOG6`: Orchestrator + UX Agent + Frontend Agent

Todos os subagentes devem consumir `docs/agents/CONTEXT_SHARED.md` antes de qualquer execucao.

## Saida esperada

Ao final de M10, o projeto deve estar com sua continuidade organizada, documentada e pronta para abrir a proxima frente com seguranca e rastreabilidade.

## Proximo passo apos M10

Apos validacao do gatilho, uma unica frente deve ser priorizada de cada vez:

- produto / piloto
- hardening tecnico / arquitetura
- UX / Figma / experiencia
